# MON-L3 interpretation questions

1. **Rule ordering and text matching** — `specs/apps/10-pure-libraries-2.md` / MON-L3 and `07-parity-backlog.md`, Money, say first match by priority but do not define ties or case sensitivity. Options: lower/higher priority first; reject ties or preserve input order; case-sensitive or insensitive text. Conservative implementation: lower numeric priority first, stable input order for ties, case-sensitive matching, all conditions ANDed. Contains is literal; glob matches the whole field using only `*` (zero or more Unicode code points) and `?` (one). Brackets, braces and backslash syntax are rejected rather than interpreted as extended glob syntax. No regex evaluation or case/whitespace normalization.
2. **Ambiguous transfer candidates** — MON-L3 specifies opposite amounts, two accounts, same currency, within N days and one-to-one matching without a tie policy. Options: closest date / input-order greedy selection, global matching, or reject ambiguity. Conservative implementation: reject any transaction with multiple eligible counterparts with a typed error; return only unambiguous pairs. N is explicit, inclusive, nonnegative whole calendar days. Dates are strict Gregorian `YYYY-MM-DD` (years 0001–9999); zero amounts are not transfers.
3. **Reconciliation baseline and marking** — `07-parity-backlog.md`, Money, lists reconciliation without a balance convention. Options: an opening ledger balance before all supplied transactions, or a previously reconciled balance that excludes reconciled entries; return proposed IDs even with a mismatch, or only when balanced. Conservative implementation: caller supplies an opening balance before every supplied transaction, a single account/currency, and statement date. Cleared and already reconciled transactions dated on/before that date contribute to cleared balance. Difference is statement minus cleared balance. Only cleared (not already reconciled) IDs are returned for marking, and only when difference is zero. No automatic adjustment or subset-sum guessing.

These choices keep the library pure and explicit; maintainer confirmation can refine them without UI or persistence changes.
