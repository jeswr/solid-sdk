# sst-230m questions and conservative resolutions

1. Which concrete Notes/Docs JSON schema should the converter target? `07-parity-backlog.md`, Notes “Existing data layer”/“Parity checklist”, and `12-pure-libraries-4.md` name the shared TipTap engine but do not supply a schema. Options: invent a second Docs dialect, or retain TipTap's ProseMirror JSON names. Resolution: retain the shared names and accept only paragraphs, headings 1–3 (05-docs §1), bold/italic/link text, bullet/ordered lists, and task lists. Reject all unsupported nodes, marks, attributes and malformed structure in either direction. No HTML conversion or resource moves.
2. What does checklist reorder address, and are checked children moved independently? The NOT-L2 task and Notes checklist row do not specify an addressing model. Options: invent document paths/IDs, or operate on the existing NOT-L1 `ChecklistItem` array. Resolution: pure array operations with zero-based indices; reorder's destination is the final index. Move checked items to the bottom stably; uncheck all changes only checked flags. Nested editor lists remain intact during conversion, with the Docs depth-three task-list limit (05-docs §4.7).
3. Which optional editor attributes belong to the shared subset? Neither spec defines extension defaults. Options: guess custom extensions, or retain only known structural/link fields. Resolution: heading `level`, ordered-list `start`, task-item `checked`, and link `href`/`target`/`rel`/`class`/`title`; optional empty attribute objects are preserved. Formatting/alignment, list styling and extension metadata are rejected. Link destinations accept absolute http(s)/mailto and suite-absolute paths (05-docs §4.6), preserving the original spelling.
