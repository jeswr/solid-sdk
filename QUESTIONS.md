# CON-02 conservative interpretations

1. **Vocabulary constants API (DESIGN §2 D4).** `@jeswr/solid-federation-vocab` explicitly has no JavaScript runtime API. Options: change that package, switch early to suite-vocab (CON-13), or isolate local constants matching its ontology files. Chosen: the third option, without dependencies or changes to the vocabulary package. All adapters have a `vocab-map.ts` seam; only existing music, calendar and social class alignments are applied. Detailed property mappings remain with CON-04/09/10/11. The scheduling ontology calls the class `CalendarEvent`, rather than the spec's `Event`; use the term that exists.
2. **State and merge semantics (DESIGN §2 D3).** Options: replace entire collections, union all statements, or replace incoming item descriptions while preserving absent items. Chosen: replace by named subject / `schema:identifier` within each deterministic slug, preserve absent items, propagate conditional-write failures without retrying or advancing the checkpoint. Adapters retain responsibility for deterministic linked-node identifiers and source-specific deletion handling. State counts describe documents and distinct item identities presented to the successful run, plus skipped items. `onState` supplies failures without storing exception text; the host alone persists state. Dates are JSON-safe ISO strings.
3. **Provenance layout and absent source URLs (DESIGN §2 D3).** Options: duplicate activity descriptions in every collection, add one document per run, or retain activities in one connector-local document. Chosen: `_provenance.ttl` contains distinct activity IRIs; collections/items link to their generating activity. The activity uses the same connector URN for every run and records start/end and source IRIs. Existing `schema:url` supplies each item's derivation; otherwise an explicit `NormalisedDoc.sourceUrl` or source-origin/export URN supplies an honest fallback. No item URL is invented. Activity writes are conditional, excluded from imported-document counts and Type Index registration. Successful runs are recorded; failed runs also attempt to record their activity without masking the original failure. Errors preserve the host checkpoint, including when the provenance write fails.
4. **Recorder policy (DESIGN §3).** Options: maintain a personal-field denylist alone, or require explicit non-personal scalar paths in addition to blocking known sensitive keys. Chosen: fail-closed allowlisting, default empty. Hosts configure public static route prefixes and non-personal JSON paths; dynamic URLs, all headers, request bodies and unlisted response fields are never saved. Known token/cookie/personal keys cannot be allowlisted. Hosts must use synthetic replacements for personal values they need in replay fixtures. The recorder exposes detached redacted fixtures for the host to save, avoiding filesystem coupling in the browser package.
