# CAL-L6 questions and conservative readings

1. **Protocol scope** — `specs/apps/12-pure-libraries-4.md` and CAL-L6 name iTIP semantics but do not prescribe identity forms, recurrence-instance handling, delegation transfers, or wire serialization. Options: implement the full protocol, or a strict whole-event planning subset. This lane takes the subset: canonical HTTP(S) WebIDs, the four standard participation roles, the five requested statuses, and REQUEST/REPLY/CANCEL data plans. DELEGATED records an RSVP only; it cannot add a delegate. Unknown fields (including recurrence IDs and delegation targets) are rejected. A future adapter owns event content, serialization, sharing, notification delivery, and authentication of the actor passed to this library.
2. **Reply ordering and attendee edits** — the same sections do not define same-sequence reply ordering or retained attendees' RSVP state. Options: use arrival order, or require explicit UTC DTSTAMP and ignore older/equal replies; reset retained statuses, or preserve them. This lane requires second-precision UTC DTSTAMP, ignores older/equal replies at the current sequence, preserves retained statuses across organizer membership/role edits, and starts additions at NEEDS-ACTION. Every explicit attendee-set edit advances SEQUENCE and clears reply-order stamps; removed attendees receive CANCEL and the remaining set receives REQUEST at the new sequence. Older-sequence replies are ignored; future-sequence replies fail closed.
