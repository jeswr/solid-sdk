# @jeswr/solid-task-model

The shared browser-safe RDF model for tasks, issue trackers, and contacts across Solid apps.

## Install

```sh
npm install github:jeswr/solid-task-model#main
```

The package tooling requires Node.js 20 or newer; every runtime entry except `/shape` is
browser-safe.

## Minimal usage

```ts
import {
  parseTaskTtl,
  serializeTask,
  type TaskData,
} from "@jeswr/solid-task-model";

const resourceUrl = "https://alice.example/issues/42";
const turtle = await serializeTask(resourceUrl, {
  title: "Add OAuth login",
  state: "open",
  assignee: "https://bob.example/profile/card#me",
  dueDate: new Date("2026-08-01"),
});

const task: TaskData | undefined = await parseTaskTtl(resourceUrl, turtle, "text/turtle");
```

Pod data is untrusted. `buildTask` drops object-property values that are not absolute
http(s) IRIs, and `parseTask` applies the same scheme check on read: a `javascript:` or
`data:` creator, assignee, project, parent, duplicate-of, cloned-from, blocked-by or
relates-to IRI is left out, as is any value with characters an IRI cannot contain, a
control character, no authority after the `//`, or a form WHATWG `URL` cannot parse. Accepted IRIs come back exactly as stored, not
canonicalised. A malformed value, such as a literal where an IRI belongs or an invalid
date, drops only that value instead of aborting the parse; a single-valued IRI field
takes the first acceptable IRI among its values.

## Key API

- Tasks: `Task`, `TaskData`, `buildTask`, `parseTask`, `parseTaskTtl`, `serializeTask`,
  `sortTasks`.
- Trackers: `Tracker`, `TrackerData`, `buildTracker`, `parseTracker`, `serializeTracker`,
  `DEFAULT_WORKFLOW`, `canTransition`.
- Contacts: `ContactBook`, `Contact`, `ContactGroup`, plus build, parse, and serialise helpers for
  address books, people, groups, and their indexes.
- Vocabulary constants for `wf`, Dublin Core, PROV-O, schema.org, vCard, ACL, and RDF.
- Node-only SHACL helpers from `@jeswr/solid-task-model/shape`; browser-safe focused entries are
  available at `/task`, `/tracker`, and `/contacts`.
- Raw shapes: `/shapes/task.ttl`, `/shapes/tracker.ttl`, and `/shapes/contacts.ttl`.

Task state is the interoperable `wf:Open` or `wf:Closed` wire model. The serializers use
`n3.Writer`; callers should not construct RDF strings manually.

## Generated Task core

Task is generated by `@jeswr/federation-codegen` and interpreted by `@jeswr/model-runtime`.
The inputs are [`codegen/task.ontology.ttl`](./codegen/task.ontology.ttl),
[`codegen/task.shapes.ttl`](./codegen/task.shapes.ttl), and
[`codegen/codegen.config.json`](./codegen/codegen.config.json). The profile header lists
every difference from the published `shapes/task.ttl` and the scheduling sector. There
is no federation-sector shape targeting `wf:Task`; this package retains its existing
workflow, Dublin Core, schema.org and PROV-O IRIs. The public shapes remain unchanged.
Tracker and contacts remain hand-written for subsequent migrations.

`src/generated/` contains the manifest, runtime shim, declarations, normalized SHACL and
input/output hashes. Never edit these files directly. The public `src/task.ts` facade
extends the generated wrapper and delegates build and literal parsing to `entities.Task`.
`src/task-types.ts` retains the original public types. `src/task-policy.ts` keeps the
first-valid IRI read policy, priority normalization, display helpers and original Store
ordering. The facade supplies lifecycle timestamps and writes both description predicates;
the shared `@jeswr/rdf-serialize` serializer preserves generic Store serialization for
Task, tracker and contacts. A build copies the generated JS and declarations to
`dist/generated/`; `dist/` is never committed.

From the workspace root:

```sh
export PATH=/opt/node24/bin:$PATH
pnpm --filter @jeswr/federation-codegen... run build
pnpm --filter @jeswr/solid-task-model run codegen
# After reviewing an intentional input change:
pnpm --filter @jeswr/solid-task-model run codegen --update-lock
pnpm exec turbo run lint build typecheck test --filter=...@jeswr/solid-task-model
node scripts/check-codegen.mjs
```

`test/codegen.test.ts` regenerates every artifact byte-for-byte, including the lockfile.
All 180 original tests remain unchanged, including the export contract, snapshots,
cross-app fixtures and hardened IRI tests. `test/compatibility.test.ts` adds byte-level
Turtle/JSON checks, strict built-declaration checks, facade policy checks and divergence
pins. The runtime dependency must remain in a published mirror: generated declarations
reference its types, so it cannot be declared inlined.

## Exact divergences

The generated guards change these edge cases outside the original oracle. Each is pinned
in `test/compatibility.test.ts`:

- **Required title:** a missing title, multiple titles, a language-tagged title or a
  non-`xsd:string` value rejects the task. Previously parse returned `""` or the first
  value's text. A stored empty string remains readable; building an empty title still
  drops it and produces a non-conforming shell.
- **Optional literals:** ambiguous values or values outside the declared datatype drop.
  This includes language-tagged text/priority, date-only or string-typed timestamps,
  impossible calendar dates and integer/decimal/string ranks instead of `xsd:double`.
  The old accessors took the first value and used permissive literal conversions.
  Description predicates are checked independently: a valid `dct:description` can now
  supply the body when `wf:description` is malformed or ambiguous. Valid workflow text
  still wins. Priority still trims and lowercases valid string text; parsed ranks remain
  finite-only.
- **Recognition and subjects:** data-graph subclasses of `wf:Task` are recognized.
  Subject helpers, build and direct wrapper construction throw `TypeError` on relative
  or unsafe IRIs; parse returns `undefined`, and document parsing checks the base before
  parsing. Direct wrapper construction also rejects blank nodes and other non-NamedNode
  terms. Safe absolute subjects keep their spelling and need not use http(s).
- **Writes:** generated text setters/build strip C0/C1 control characters while retaining
  tab, newline and carriage return. Invalid dates drop instead of throwing; a closed
  task still receives a completion timestamp. Expanded and negative years use valid XSD
  dateTime spelling (`10000-…` / `-0001-…`), and non-finite doubles use `INF`, `-INF`,
  `NaN`; parse still omits non-finite ranks. IRI field writes drop values with forbidden
  characters surviving URL normalization, and `types.add` throws on unsafe IRIs.
- **Direct Task accessors:** generated literal getters use the same datatype/cardinality
  rules; IRI getters normalize spelling, scalar ambiguity drops and IRI setters/live
  sets apply http(s) guards. Previously the wrapper exposed raw mapper values. The public
  plain-data parsers retain the hardened IRI contract: read each object, keep exact stored
  spelling (including uppercase schemes), select the first valid scalar and retain every
  valid set member. These reads never mutate the dataset.
- **Retained direct reads:** to keep consumer validation working, a scalar date
  accessor returns an Invalid Date for a lone literal typed `xsd:dateTime` that
  `new Date(lexical)` cannot parse either, as `LiteralAs.date` did. A lenient non-XSD
  form the old wrapper parsed (`2026-03-01`, `2026-03-01T00:00Z`, `…+0000`) and an
  impossible calendar date such as `2026-02-30T00:00:00Z` (which rolled over to
  2 March) now read as `undefined` instead of a Date. Closing a task replaces a
  malformed stored completion time with the current time. A scalar IRI accessor returns the exact spelling of a lone http(s) IRI
  that `URL` cannot parse, such as `http://a%zz/`. The IRI must have an authority and
  no forbidden or control characters. Plain-data `parseTask` still drops both values.
  Ambiguous, otherwise-typed, non-http(s) and lexically unsafe values stay dropped.
- **Plain-data IRI reads:** besides the scheme and IRIREF checks, a stored http(s) IRI
  with a C0/C1 control character, an empty authority (`http:///x`) or a form `URL`
  cannot parse is dropped. The original parser returned the raw value.

The remaining generator/runtime gaps are explicit: `rdf:type` is reserved and cannot
project the qualified exactly-one-state constraint; aliases write canonical-only and
cannot write both description predicates; and normalized singleton IRI projection cannot
express first-valid recovery with exact lexical identity. State uses generated `types`
and `endedAt` accessors, descriptions use two generated fields, and IRI reads retain the
package's existing guarded object-by-object policy. No generator or runtime code is changed.
