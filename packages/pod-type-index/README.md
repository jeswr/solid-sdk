# @jeswr/pod-type-index

**Experimental — AI-agent-generated.** Discover RDF classes across Solid Type Index documents
and LWS TypeIndexService / TypeSearchService endpoints.

```ts
import { createTypeIndex } from '@jeswr/pod-type-index';

const index = createTypeIndex({ storage, features, profile: webId, fetch: authFetch });
const locations = await index.find('https://schema.org/TextDigitalDocument');
const byClass = await index.findAll([documentClass, taskClass]);
const hint = await index.register(documentClass, { container: documents });
// On LWS, declare types when creating each resource (container types describe the container).
await storage.create(documents, body, { contentType: 'text/turtle', ...hint });
await index.unregister(documentClass, { container: documents });
```

`register` and `unregister` require exactly one `container` or `instance`. Their optional third
argument is `{ index: 'private' | 'public' }` (default `private`). Solid registration returns
`undefined`; LWS returns `{ links: [{ rel: 'type', target: canonicalClass }] }` without I/O.
LWS unregister is also a no-op: the server owns its index, and deleting resources removes their
entries. `listClasses()` reads the LWS TypeIndexService; on Solid it throws `unsupported`.

Solid discovers public indexes on the WebID subject in the profile and private indexes through
`pim:preferencesFile`; legacy private links directly in the profile are also read and maintained.
`findAll` reads each document once per call, even for shared index URLs and multiple classes.
Locations are de-duplicated, containers are returned as locations rather than traversed, and known
legacy class namespaces from `@jeswr/suite-vocab` are accepted. New registrations use canonical IRIs.
Missing linked indexes yield no locations; unreadable or invalid documents propagate errors.

On a bare profile, registration creates `settings/privateTypeIndex.ttl`, types it as a TypeIndex
and UnlistedDocument, links it from `settings/prefs.ttl`, then links preferences from the profile.
Public registration creates a ListedDocument and links it directly from the profile. Existing
preferences and unrelated RDF are retained. Existing default-path documents are adopted only when
typed as TypeIndex. Bootstrap requires reported root Write and Control access. Only a confirmed 404 permits creation, using `storage.create`'s exact-name
Solid PUT with `If-None-Match: *`. Edits require a strong observed ETag and `writeRdf` with `ifMatch`;
no wildcard overwrite is used. Conflicts re-read/reconcile at most twice. An interrupted bootstrap
may leave an unlinked index; repeating registration reuses it. No-op changes avoid writes.
Unregister removes only the exact class/location registration, keeps other entries and annotations,
and refuses ambiguous multi-class or multi-location entries. If legacy profile and preferences
private pointers identify distinct indexes, unregister rejects with `conflict` before writing.
It does not delete documents/links.

All document and result URLs must be HTTP(S), credential-free, and inside the selected storage.
Foreign profile documents are unsupported by this storage-scoped API. Reads drop unsafe linked
URLs; mutations reject them. Data discovery grants no access. Bootstrap inherits the destination
container's access controls: callers must provision owner-only settings/preferences/private-index
access through their access layer before registration. The UnlistedDocument type itself is not
an ACL. This package does not modify access controls or make the profile private.

LWS requires advertised, available server type-index features. `findAll` sends one QUERY with an
OR group containing all requested classes and known aliases, partitions returned resource types,
and follows opaque next links with GET. `fetch` must be the guarded authenticated transport used
by storage; it is needed because StorageClient has no QUERY method. All other I/O uses the public
StorageClient API. No global fetch fallback or backend imports are used. Service endpoints and
pagination stay within storage scope. Each operation has a 30-second transport deadline, at most
64 documents/pages and 10,000 matching locations/items; LWS JSON pages are capped at 1 MiB.
Overflow rejects instead of returning misleading partial results. Results are never cached across
operations/accounts, and LWS results may reflect eventually consistent server derivation.

The `./testing` entry re-exports `createMemoryStorage` for offline fixtures. The React façade
package `@jeswr/suite-sdk` currently provides notifications; it does not yet expose `useTypeIndex()`.
Type index provider/hook integration is owned by SDK-APP-01. A future hook can hold this client per
selected account/storage.

## Generated RDF model

The Solid RDF core is generated by `@jeswr/federation-codegen` and interpreted by
`@jeswr/model-runtime` (sst-ild.4.7). The minimal ontology, discovery SHACL profile, and config
live in [`codegen/`](./codegen/). There is no federation sector for Type Indexes. All existing
Solid/PIM IRIs are retained exactly. `src/generated/` contains the manifest, typed shim,
normalized shapes, and input/output hashes; never edit these files by hand.

`src/rdf.ts` delegates named-subject registration build/parse, TypeIndex typing, and profile pointer
access to the generated entities. It serializes the whole document with `n3.Writer`, using the
runtime's exported quad validation and round-trip integrity checks. `Resource` remains a minimal
internal typed view for raw validation evidence and blank-node registrations. `IndexDataset`
enumerates independent subjects and applies the generated registration entity to each named
subject. `src/solid.ts` retains network discovery, URL scope and alias policy, bounded results,
conditional writes, bootstrap, reconciliation, and exact removal. The LWS backend is unchanged.
The public exports and types, including `./testing`, remain compatible.

The profile header documents the generator gaps and projection choices:

- A document has any number of independent registrations, with no linking predicate from the
  TypeIndex subject. Generated composites require a connected tree, so document listing stays
  in the facade.
- Generated wrappers accept only named subjects. Blank registrations use the typed view for
  reads and removal, preserving their identity, other types, and annotations.
- Closed admission cannot express `sh:xone` for `instance` versus `instanceContainer`. The
  discovery profile uses optional IRI sets to preserve tolerant multi-value reads; the existing
  mutation API enforces exactly one location, and removal checks raw cardinalities, including
  malformed members. Class IRIs can use non-HTTP schemes. Scope and container policy stay in
  the facade rather than changing lexical RDF identities through a generated URL guard.
- Generated reads span graphs, so the facade supplies only each subject's default-graph data.
  Untyped profile/preferences subjects use the generated Profile wrapper directly; no Agent
  type is required or added. ListedDocument/UnlistedDocument remain extra type markers.

Builds copy the generated JavaScript and declarations into `dist/generated/`. The original
140 tests remain unchanged. `test/codegen.test.ts` regenerates every artifact into a temporary
directory and compares bytes, including the lock. `test/compatibility.test.ts` pins tolerant
named/blank subjects, raw cardinality checks, graph isolation, lexical removal, untyped profiles,
valid Turtle bytes, and the divergences below. Coverage remains 100% for statements, branches,
functions, and lines.

## Exact divergences

The generated runtime tightens these edges outside the original oracle. Each is pinned in
`test/compatibility.test.ts`:

- A relative named registration subject supplied by a custom/injected RDF transport is ignored
  (`ignores a relative named registration subject from an injected RDF dataset`). Ordinary
  document parsing already resolves relative subjects against the document URL. Blank-node
  registrations remain supported.
- Full-dataset serialization rejects unsafe unrelated IRIs and unrepresentable RDF terms
  instead of emitting unchecked Turtle (`rejects unsafe unrelated IRIs at serialization
  without rewriting their identity`, and `rejects RDF terms that cannot retain their identity
  in Turtle`). This includes relative subjects/predicates/datatype IRIs, invalid blank labels,
  and malformed language tags. It does not escape or normalize the stored identity.
- Serialization rejects output that loses triples or otherwise changes RDF identity
  (`rejects a serializer result that silently loses triples`). Valid RDF serializes to the
  original N3 bytes without changing the dataset. Original N3 callback errors still propagate
  unchanged, as required by `src/validation.test.ts`.
- Solid registration and unregistration reject targets that fail the runtime's safe absolute
  IRI guard with `StorageError` code `scope` before I/O. This includes raw `|` in a path,
  and `{`, `}`, `|`, or `^` surviving URL normalization in a fragment. Absolute-looking class
  IRIs that the runtime cannot parse also fail with `scope`. Invalid inputs already rejected
  by the original class/visibility/container contract retain their original errors. These
  input divergences are pinned by `rejects runtime-unsafe mutation targets before I/O` and
  `rejects an absolute-looking class that the runtime cannot parse before I/O`. Defensive
  build assertions are covered separately in `test/review-regressions.test.ts`.
- Runtime-unsafe WebIDs and storage roots reject at client construction with `StorageError`
  code `scope`, preventing raw runtime `TypeError`s and any I/O (`rejects a runtime-unsafe
  WebID with StorageError/scope`, `rejects a runtime-unsafe storage root with StorageError/scope`).
- Stored profile/preferences pointers with runtime-unsafe IRIs are hidden during discovery;
  strict registration and unregistration reject them with `scope`, without writes. This
  applies to `publicTypeIndex`, `privateTypeIndex`, and `preferencesFile`, including values
  preserved by JSON-LD parsing (`hides runtime-unsafe stored pointers on discovery and rejects
  strict mutations`). Valid sibling pointers remain discoverable.
- Stored locations on named registrations with runtime-unsafe IRIs are hidden from `find`,
  while valid sibling locations remain visible. Raw values still count for removal ambiguity,
  so unregister cannot silently delete only the visible member (`hides runtime-unsafe stored
  locations while retaining valid siblings`). The JSON-LD tests cover both `instance` and
  `instanceContainer`; blank registrations retain the original typed view.

## App migration candidates

The public `createTypeIndex(...).find(classIri)` / `findAll(classes)` list class locations and
`register(classIri, { instance | container })` adds registrations. With an account-scoped public
StorageClient, these can replace discovery/registration code in the following call sites:

- `apps/suite/src/apps/drive/lib/model/type-index.ts`
- `apps/suite/src/apps/tasks/lib/model/type-index.ts`
- `apps/suite/src/apps/mail/lib/model/typeIndex.ts`
- `apps/suite/src/apps/contacts/lib/model/discovery.ts`
- `apps/suite/src/apps/sheets/lib/model/storage.ts` and `lib/workbook/registration.ts`
- `apps/suite/src/apps/docs/lib/model/type-index.ts`
- `apps/issues/src/lib/type-index.ts`
- `apps/pod-mail/src/model/typeIndex.ts`

No apps are changed by this flip. App-specific access-control provisioning and document
annotations remain the apps' responsibility; `find` returns locations rather than raw entries.
