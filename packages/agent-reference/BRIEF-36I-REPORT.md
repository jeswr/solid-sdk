# Brief 36i report

The continuation guard now uses one whole-value matcher for releases and the evidence
that can explain them. The round 9 regressions cover the original failures and the
allowed counterparts.

| Review item | Regression coverage |
| --- | --- |
| Refused values equal to an issuer or subject | Copies of either value from `terms` fail under a renamed field. |
| Party-signed derivation | A statement issued by the refusing agent's party cannot explain a store or a cited packet body, even after that agent admits it. |
| Citation to a different account | `urn:account:123` and `urn:account:1234` stay distinct in both directions. The exact account in an independently admitted citation explains the copy. |
| Changed statement digest | Replacing the stored record at a cited ID invalidates the earlier admission for that citation. |
| Duplicate JSON members | The guard checks raw JSON values before parsing the object. The tests cover overwritten IDs and values, a Unicode escape, compact payloads and UTF-8 byte arrays. Structural field names alone still pass. |
| Policy-like parameter objects | A copied `action: "anonymize"` fails even with a sibling `type` field. |
| Approved email | The released body `text: confidential` fails after refusal of `text`. An unrelated email with the structural `text` key still passes. |
| Native credential projection | A signed native packet carrying the unchanged, independently admitted credential passes without a citation. A copy in the packet body and a credential with changed bytes both fail. |

An exemption requires admission in the refusing agent's own inbound gate and a matching
claim or wire digest. The issuer must differ from the agent's party. A native credential
exempts only its verified RDF projection, rebuilt from the original bytes and compared
with the graph. The guard checks refused IDs and digests even inside those projections.
