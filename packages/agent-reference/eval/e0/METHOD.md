# E0 method and limits

Run `pnpm --filter @jeswr/agent-reference eval:e0`. The seed defaults to 20261113 and N to 200. Optional arguments are `--seed=NUMBER`, `--n=NUMBER`, `--scenario=ID` and `--out=DIRECTORY`. A subset run writes a subset report. Use `--out` to preserve the full report. Node 24, the installed workspace are prerequisites. The command builds workspace dependencies and compiles this package before running. No model, provider, socket or network is used by the evaluation.

`scenario-runs.json` is the coverage authority. This checkout uses `runs`, not `agrees`, for an agreeing runnable path. Include `runs`, `agrees` and `disagrees`; exclude `blocked`. `catalogue.json` preserves the sector mapping from the supplied fictional catalogue. `spec-clauses.json` records the normative files and their SHA-256 digests for every mutation clause. Tests check the actual specification files when available; the index also makes tests portable to checkouts without the mounted project files.

Observers wrap the existing runtime entrypoints in this process only. They are restored in a finally block. Outbound probes swap in copied state, gate memory, both gates and an in-memory ledger for a synchronous transaction. Inbound replays construct new runtimes with copied state, fresh stores and ledgers, and copied authority caches. They preserve the checkpoint clock, carriage, approval context and mutable gate-memory bindings. They stop on the first inbound decision, before a handler runs. Direct claim batches complete all their claim checks. Capability services run their real request/query/read entrypoints against fresh stores. No runtime, gate, scenario, profile or original trace source is edited. Every baseline outline is checked against the existing oracle, which also detects observer events leaking into the baseline.

A generates all applicable mechanical substitutions at every non-resuming core authorisation. Held items include facts, messages, opaque content and readings. Numeric substitutions use the principal's amount and retention limits and payment rule limits. The repeat test applies the real release and seal paths, including approval consumption and payment reservation. For each single-use action, a supplemental repeat uses an isolated adapter and a copy of the atomic register from the proposal checkpoint. It runs two distinct effect keys and records how many executions occurred, together with both register and runtime records. A first attempt that could not complete is reported as such. Each random proposal starts with an observed typed template; payment proposals retain the payment shape. Paths without a scripted proposal get N proposals against their final state. Every unmodified scripted proposal is also checked in the clone and compared with the actual runtime decision; a mismatch aborts the run as a harness error. Each path's random stream is derived independently from the seed and path identifier.

The reference evaluator does not call the gate or the ODRL engine. It reads exact actions and targets, assignees, recipient/purpose/time constraints, prohibitions and approval bindings. It leaves standing emergency grants and registration requirements unresolved. The production ODRL evaluator deliberately gives `use` broader action semantics. These disagreements require adjudication. Property failures are retained individually with causes, proposals, decisions, gate events and trace names. Reproduction state and mandate dictionaries avoid repeating large snapshots. A proposal release does not prove its eventual payload would pass a subsequent message check. The record predicate checks the proposal's write-ahead authorisation; it does not prove durable filesystem behaviour or external transmission ordering.

B has a clause/check/verdict/reason table independent of the observed result. It mutates signed content using deterministic fixture keys, re-signs enclosing messages when changing a nested credential, and keeps the pre-input state fixed. A changed claim counts as a false admit only if that specific claim passes admission again. Existing facts are not mistaken for new admission. Removal of a required claim is scored at the envelope boundary. Optional rejected claims can be stripped while an envelope is admitted. Alterations to originally refused inputs are kept in the results, so earlier failures can mask the check targeted by a mutation. Missing status channels, profile value-shape definitions and inbound single-use consumption are explicit limitations or unspecified cases. A credential's shape is tested by breaking its required claim type; these profiles do not generally declare per-value schemas.

C generates six plans per participating actor. Supported plans replay the existing transfer or commitment, suppress a receipt, append a same-key signed denial of a recorded acknowledgement, send a held item for a forbidden purpose, or send after local withdrawal. These last two faults deliberately use the dishonest party's fixture signing key outside its own outbound gate, then pass the actual wire through the receiver's real gate. A withdrawal is made through the sender runtime before the injected send. A terms-after-approval change uses a checkpoint with an actual approval or recorded agreement acceptance. A different signed commitment uses the original signed commitment as the simulated principal's displayed value. Injected later messages get fresh identifiers and times, so an unrelated identifier-reuse fault cannot give the checker the answer. There is no user-interface study and no new displayed-value evidence is inserted into the record. Both real record prefixes and the replay records are retained. Receiver refusal is recorded separately; signing and transmitting the bad message is already an act. A denied proposal alone is never attributed as a withdrawal breach. A receipt is withheld only when the baseline actually produced one. Services without a principal mandate or later outbound interface cannot execute some plans. Those plans are listed individually and excluded from attribution scores. No signed assertion that a fault happened is substituted for running it.

The checker receives only party identifiers, hash-chained entries and exact protected messages from the two records. It checks chain consistency, withdrawal/observed-message bindings, item terms available in those messages and acknowledgement/denial contradictions. It returns cannot-tell when evidence is missing or more than one breach is supported. It does not fetch keys or notarize a ledger's completeness. The identity and signature provenance of exported records remains an assumption of this local consistency check. Missing receipt deadlines, absent displayed digests and unwitnessed downstream use are findings. The current checker cannot establish those facts by reading an injected label.

The four JSON result files have deterministic content for a fixed commit, seed, N and inputs. Elapsed wall time appears only in the Markdown summary. An output directory lets a second run be compared without overwriting the first. Compact counts are intended for the explorer to bundle; full records stay in the detailed files. The lane does not modify the explorer application.

For a small reproduction of the missing-required-claim failures, run `PATH=/opt/node24/bin:$PATH pnpm --filter @jeswr/agent-reference eval:e0 --scenario=benefit-claim --n=0 --out=/tmp/e0-benefit`. The mutation report contains the three main-path missing-kind false admits. Admission.complete checks required failures only for supplied claims in its cache; a removed kind has no entry to check. Ambiguous mutation expectations use null for check, verdict and code, with two explicit readings. No code is guessed for those trials.
