# @jeswr/solid-drawing

RDF vocabulary and typed helpers for describing an Excalidraw-compatible scene stored in a Solid pod.
The scene model is generated by `@jeswr/federation-codegen` and interpreted by
`@jeswr/model-runtime`, behind the existing function-based API.

The RDF descriptor holds metadata and points to the byte-exact `.excalidraw` JSON resource; it does
not split the canvas into triples.

Writers and the shipped ontology/SHACL files use `https://jeswr.org/ns/drawing#`
(source: `@jeswr/suite-vocab` NS.DRAWING_APP), with ontology core references under
NS.CORE, `https://jeswr.org/ns/core#`. Readers also accept the read-only legacy
namespace exported as `LEGACY_DRAW_NS`, including mixed canonical/legacy data.
Cardinality checks span both aliases: identical values agree, conflicting canvas
links reject the scene, and conflicting optional values are omitted.

> Experimental. Review the model before using it for long-lived data.

## Install

```sh
npm install github:jeswr/solid-drawing#main @rdfjs/types
```

Requires Node.js 20 or newer.

## Minimal usage

```ts
import { parseSceneTtl, serializeScene } from "@jeswr/solid-drawing";

const sceneUrl = "https://alice.example/drawings/diagram.ttl";
const turtle = await serializeScene(sceneUrl, {
  sceneDocument: "https://alice.example/drawings/diagram.excalidraw",
  title: "System architecture",
  schemaVersion: "2",
  thumbnail: "https://alice.example/drawings/diagram.png",
});

const scene = await parseSceneTtl(sceneUrl, turtle, "text/turtle");
```

## Key API

- Scene data: `buildScene`, `serializeScene`, `parseSceneTtl`.
- Vocabulary constants: `DRAW_SCENE`, `DRAW_SCENE_DOCUMENT`, and matching `*_IRI` strings.
- Node-only assets: `drawingShapeTtl` and `drawingOntologyTtl` from `@jeswr/solid-drawing/shape`.
- Bundled files: `drawing.ttl` and `drawing.shacl.ttl` subpath exports.

## Generated model

[`codegen/`](./codegen/) contains the generation-only ontology, SHACL profile and config.
The committed `src/generated/` holds the manifest, typed runtime shim, normalized SHACL
and input/output hashes. [`src/scene.ts`](./src/scene.ts) is the thin facade: all nine
scene fields build and parse through `entities.Scene`. There was no public accessor
class to preserve. Vocabulary constants and [`src/iri.ts`](./src/iri.ts) stay hand-written.
The original 90 tests, including the IRI differential test, remain unchanged.

The facade keeps the existing required-link `TypeError`, lexical IRI escaping, string
rather than `Date` timestamps, and singleton cardinality across canonical/legacy
predicates. Config disables text sanitization for the three text fields to preserve
literal content, including empty strings and controls. A minimal typed lexical view
carries non-string/language-tagged version and background literals that the generated
profile cannot admit. Generic `storeToTurtle` still uses `@jeswr/rdf-serialize` and
preserves arbitrary Stores' legacy terms; `serializeScene` uses the generated serializer.

The [profile header](./codegen/drawing.shapes.ttl) lists every difference from the
[federation drawing sector](../solid-federation-vocab/sectors/drawing/drawing.shacl.ttl):
keep the package namespace, accept its existing w3id aliases, make the title optional
and singleton, and add its timestamp/background/about/provenance fields. The sector's
required title is deliberately relaxed to preserve the oracle. Sector profile metadata
is omitted. The package's published arbitrary-literal version/background constraints
are narrowed to `xsd:string` only in the codegen profile, with public reads carried by
the facade. `drawing.ttl`, `drawing.shacl.ttl`, their subpath exports and the Node-only
`/shape` helpers continue to expose the unchanged published package profile.

Generator/runtime limitations handled here:

- Closed admission requires a concrete literal datatype; it cannot project the published
  `sh:nodeKind sh:Literal` without one. The generated version/background fields use
  `xsd:string`; the facade's typed view preserves other literals' lexical values.
- Runtime singleton aliases use canonical-first selection rather than the drawing
  oracle's union cardinality. The facade rejects/drops conflicts using generated alias
  metadata, including mistyped legacy values. The generated SHACL checks the union.
- Runtime `iriScheme` guards normalize URLs, whereas drawing preserves lexical RDF
  identity. The facade keeps the existing write guards; config omits scheme guards.
  Reads retain safe absolute IRIs of any scheme, as before.
- Generated dateTime fields project `Date`, with no lexical-string mode. The facade
  converts with the runtime's strict reader/writer, preserving the public string type.

From the workspace root:

```sh
export PATH=/opt/node24/bin:$PATH
pnpm --filter @jeswr/federation-codegen... run build
pnpm --filter @jeswr/solid-drawing run codegen
# For an intentional ontology/profile/config change, accept the reviewed input hash:
pnpm --filter @jeswr/solid-drawing run codegen --update-lock
pnpm exec turbo run lint build typecheck test --filter=...@jeswr/solid-drawing
node scripts/check-codegen.mjs
```

Never edit `src/generated/` by hand. `test/codegen.test.ts` runs the package command into
an empty temporary directory and compares all six files byte-for-byte, including the
lock. The build copies the generated JS and declarations to `dist/generated/`;
`dist/` is never committed here. `@jeswr/model-runtime` remains a non-inlined runtime
workspace dependency for mirror publishing; the generator is build-time only.
The package-specific maintenance skill is [`SKILL.md`](./SKILL.md).

## Exact divergences

Every behavior change from the hand-written model is pinned in
[`test/compatibility.test.ts`](./test/compatibility.test.ts):

| Change | Pinned test |
| --- | --- |
| Malformed, impossible or out-of-JS-range `xsd:dateTime` timestamps drop on both read and write. Previously any lexical form with that datatype was retained/written. | `drops malformed typed timestamps on reads and writes` |
| Timestamp strings use canonical UTC with millisecond precision. Offsets and missing zones normalize to UTC, excess fractional digits truncate; expanded/negative years use valid XSD spelling. Previously timestamp strings retained their original lexical spelling. | `projects timestamp strings to canonical UTC at millisecond precision` |
| Types reaching the canonical or legacy Scene class through data-graph `rdfs:subClassOf` now count as scenes, using the runtime's bounded, cycle-safe walk. | `recognises data-graph subclasses of %sScene` |
| DEL/C1 controls (U+007F–U+009F) in subjects or required canvas IRIs throw; optional IRI writes/reads drop them, and an unsafe required IRI rejects the read. The old scene model accepted these lexemes. The exported IRI helpers remain unchanged. | `rejects C1 controls in subjects/required IRIs and drops them in optional IRI writes` |
| Unsafe or relative IRI field values on read now drop; an invalid required canvas link rejects the scene. Previously raw NamedNode values were returned. | `drops unsafe or relative IRI reads and rejects an unsafe required canvas link` |
| Store/Turtle predicates and plain-data JSON keys follow generated order, with timestamp strings appended to parsed objects. RDF values retain their meaning; serialized bytes/key insertion order differ from the old field order. | `pins generated predicate and JSON field order` |

Compatibility pins also cover arbitrary-literal version/background reads, conflicting
aliases, repeated values across named graphs, exact IRI identity, generic Store
serialization, unchanged text content, built-package imports, and both TTL subpaths.
