# @jeswr/solid-mail

> **Experimental, AI-agent-generated.** Lives in `packages/solid-mail` of the
> [`jeswr/solid-sdk`](https://github.com/jeswr/solid-sdk) workspace. The mail model
> is generated by `@jeswr/federation-codegen` and interpreted by
> `@jeswr/model-runtime` (sst-ild.7 / sst-ild.4.7;
> [design of record](../../decisions/0003-domain-model-codegen.md)).

Browser-safe live RDF wrappers for `Message`, `Thread`, `Folder` and `Attachment`,
plus `MailboxDataset`, `parseMailbox` and synchronous `serialiseToTurtle`. The API
follows the model in `apps/suite/src/apps/mail/lib/model/`; apps switch separately.
Storage I/O, operations, importing, paths, Type Index and HTML helpers stay in apps.

Install in the workspace with `"@jeswr/solid-mail": "workspace:*"`.

```ts
import { parseMailbox, serialiseToTurtle } from "@jeswr/solid-mail";

const mailbox = await parseMailbox("", "https://alice.example/mail/messages/1.ttl");
const message = mailbox.createMessage("https://alice.example/mail/messages/1.ttl#it");
message.subjectLine = "Hello";
message.sender = "mailto:alice@example.org";
message.to.add("mailto:bob@example.org");
message.setRead(true);
const turtle = serialiseToTurtle(mailbox);
```

All fields are optional. Scalar setters accept `undefined` to clear a field;
recipient, membership and attachment properties are live `Set<string>` views.
Read state derives from `dateRead`. `Thread.markThread()` adds both
`schema:Conversation` and `sioc:Thread`; mailbox enumeration selects the former.
Wrapping an attachment at its binary IRI never adds a type automatically.
Decoded `bodyHtml` is inert data and must be sanitized before rendering.

The root and `/message`, `/thread`, `/folder`, `/attachment`, `/mailbox`,
`/serialise` and `/vocab` entries expose the corresponding model modules.
Vocabulary exports retain the app's exact names and IRIs, including
`http://schema.org/`, SIOC and Dublin Core. A test compares them with the shared
pod-connectors constants; pod-connectors is not a runtime dependency.

## Generated core and facade

`codegen/mail.ontology.ttl` documents reused classes; `codegen/mail.shapes.ttl`
defines the package profile. There is no federation mail sector to narrow. The
profile models every existing accessor: optional scalar strings/dates/IRIs,
unbounded IRI sets, and integer attachment sizes. Links remain flat IRIs so sibling
documents, contact addresses and dangling memberships remain representable.
The shapes header lists every narrowing and omitted unused vocabulary term.

The six artifacts in `src/generated/` contain the manifest, runtime shim, precise
declarations, normalized SHACL and hashes. Every entity field delegates directly
to its generated wrapper. The small subclasses retain the existing names,
read-state policy, SIOC co-typing and membership convenience methods.
The declaration adapter preserves clearing setters for strict TypeScript users.

`MailboxDataset` retains the existing typed document enumeration and mint/find
methods. Complete-document parsing uses `@jeswr/fetch-rdf`, serialization uses
`n3.Writer`; arbitrary sibling triples are retained. These document APIs preserve
the synchronous serializer and whole-document return type, which the generator's
asynchronous single-entity data projections do not expose. No accessor is
hand-composed and no required shape constraint is bypassed.

The committed config uses `self` subjects, keeping caller-provided subject IRIs,
and disables text sanitization to preserve decoded mail text and HTML exactly.
There are no defaults, whitespace normalization, IRI canonicalization or
HTTP-only filters; safe absolute `mailto:`, `urn:` and HTTP(S) IRIs remain valid.
The document parser keeps the app's existing fetch-rdf defaults and Turtle format.

## Exact divergences

The five original model test suites (28 tests) pass with imports changed only.
Stricter generated accessors differ on malformed or ambiguous data; each case is
pinned in `test/compatibility.test.ts`:

- A scalar with several distinct RDF values returns `undefined` instead of the
  first value. Set fields remain sets.
- Text getters require `xsd:string`; language-tagged and other typed literals
  and non-literal terms drop instead of returning their lexical text. Wrong term
  kinds for IRI/date/number fields drop instead of throwing. The original RDF
  terms stay in the document when unrelated fields are edited and serialized.
- Date getters require a valid `xsd:dateTime`. `xsd:date` values formerly parsed,
  malformed/overflow dates formerly returned Invalid Date or rolled forward, and
  plain-string dates formerly threw; all now drop. An invalid Date write clears
  the field instead of throwing.
- Attachment sizes require safe integers typed `xsd:integer`. Other numeric
  datatypes, fractional and unsafe integers drop. Negative integers remain valid,
  preserving the old API's lack of a non-negative size rule.
- Constructors reject relative/unsafe IRIs and non-NamedNode terms with
  `TypeError`, including during enumeration of a blank-node subject with a mail
  type. Invalid IRI fields drop on read/write (clearing a scalar on write);
  invalid type-set additions throw. Safe absolute IRIs preserve their exact
  lexical spelling.

The generated wrappers additionally expose `id`, `isInstance` and `mark()`.
`isInstance` recognizes data-graph subclasses. Existing mailbox enumeration stays
exact-type based, so this does not broaden `messages`, `threads` or `folders`.
No new type is added simply by constructing a wrapper.

## Differences between the app copies

The shared package follows suite's newer model. Compared with `apps/pod-mail`:

- `Message` adds `bodyHtml`, `encoding`, `identifier`, `folderIris` and `attachments`.
- Suite has the `Attachment` metadata wrapper (`size`, `name`, `contentType`, `types`);
  pod-mail has none.
- Suite's vocabulary additionally exports `Predicates.articleBody`, `.encoding`
  and `.container`. Shared constant values are identical.
- Suite's serializer throws for named graphs; pod-mail passes them to N3 Writer.
- `parseMailbox(text, url)` exists in suite's `io.ts`, uses `parseRdf` over Turtle
  and returns `MailboxDataset`; pod-mail has no standalone equivalent.
- The shared `Message` fields, `Thread`, `Folder`, `MailboxDataset`, well-known
  folder slugs and prefix map otherwise behave identically.

These are model-scope differences. Each app retains its own I/O, paths, importer,
operations and Type Index behavior for the later switch PRs.

The excluded directory surfaces also differ. Suite's Type Index registration
clears an existing instance/container value when that location is omitted;
pod-mail preserves the omitted side. Suite uses validated account-specific paths,
tilde-escaped identifiers, reserved system-folder keys and attachment URLs;
pod-mail has account-free paths and percent-encoded identifiers. Suite supplies
operations, MIME/mbox importing and HTML helpers that have no counterparts in
pod-mail's model directory.

The stores have different APIs and policies: suite requires an injected fetch and
storage root, confines redirects/requests to that pod, refuses remote JSON-LD
contexts and imports, allows 16 MiB RDF terms on message loads, exposes
`load(url, create)`, generic binary/text `write`, `list`, `snapshot`, `mutate` and
`register`, and reports `MailError` codes/status. It requires strong ETags with no
unconditional-write option, refuses write redirects, and refreshes `etag`/`exists`
after saving, optionally from another dataset. Pod-mail defaults to global fetch,
uses `loadOrEmpty`, separate error subclasses/`mapFetchError`, ordinary fetch-rdf
limits, allows an explicit unconditional save without an ETag, accepts any
non-null ETag and leaves loaded metadata unchanged after save. These differences
are outside the shared package and must stay separate during the app switches.

## Development

```sh
export PATH=/opt/node24/bin:$PATH
pnpm --filter @jeswr/federation-codegen... run build
pnpm --filter @jeswr/solid-mail run codegen --update-lock
pnpm exec turbo run lint build typecheck test --filter=@jeswr/solid-mail
pnpm run lint:root
```

Never edit `src/generated/` by hand. `test/codegen.test.ts` regenerates all six
artifacts byte for byte, including the lock. The build copies the generated JS and
declarations into `dist/generated/`; `dist/` is never committed. The original
tests are unchanged except imports; additional tests cover attachment metadata,
the complete suite field surface, vocabulary parity and strict consumer types.
No mirror repository is configured for this new package.
