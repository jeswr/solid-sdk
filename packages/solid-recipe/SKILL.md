# Solid recipe model

Recipes (`http://schema.org/Recipe`) and weekly plans
(`https://jeswr.org/ns/recipe#MealPlan`) use the generated model in
`src/generated/model.js`. `src/model.ts` is a thin facade for validation and ordered
text. Never edit `src/generated/`; change `codegen/recipe.ontology.ttl`,
`codegen/recipe.shapes.ttl` or `codegen.config.json`, then run
`pnpm --filter @jeswr/solid-recipe run codegen --update-lock`. The byte-for-byte drift
test and the README's "Exact divergences" regression pins must pass.

The composite Recipe includes optional NutritionInformation and personal Review →
Rating nodes. No federation recipe sector exists in this revision; profile
narrowings are documented in the SHACL header. MealPlan is generated with one
optional recipe subject IRI per weekday and optional `schema:startDate` (`xsd:date`,
a Monday at midnight UTC), mirrored into `schema:name` for existing week lookups.
The facade still reads legacy name-only weeks. The pod model reads and writes only
`http://schema.org/` classes and properties, following the suite convention.
`pnpm run codegen` calls `@jeswr/federation-codegen` directly to regenerate the single
profile, and the drift test compares every generated byte.

Standard `schema:recipeIngredient` and `schema:recipeInstructions` always contain
clean text. Private `recipe:orderedIngredient` and `recipe:orderedInstruction`
copies encode six-digit positions to preserve order and duplicates. Decode only
those private values; external standard strings, even `123456: hi`, are text.
Accept private copies only when all positions are prefixed, unique, contiguous
from zero and capped at 2,000 items, and the decoded set matches the standard set.
`decodeOrdered` returns undefined for invalid copies; fall back to standard strings.
The prefix pattern is checked in the facade because closed admission rejects it.
Repeated composite children and RDF lists are not admitted by the generator.
Do not rewrite RDF strings to change namespaces. Keywords trim, drop blanks and
sort on read.

`fromSchemaOrgJsonLd`, `extractRecipeJsonLd` and `importRecipe` are inert and
network-free. Keep the input and traversal bounds. `durationMinutes` accepts
nonnegative fixed cooking durations in XSD lexical form; only seconds may be
fractional. `durationFromMinutes` normalises numeric form input into whole hours,
minutes and decimal seconds at microsecond precision. `normalizeDuration` omits
invalid, unsupported or unsafe-size optional imports. `scaleIngredient` affects
only an initial quantity or range.

`openRecipeStore` uses fixed container names and optional private Type Index
registration on Solid. On LWS it discovers server-assigned collection identifiers
by their type markers. `recipeStore(storage, container, planContainer?, ownerWebId?)`
defaults to co-location. Pass the owner WebID and authenticated storage transport
to enable owner-only verification before writes. Listing uses bounded reads,
includes legacy co-located plans, and reports unreadable files in `skipped`.
Nullable or weak ETags permit reading. Follow-up writes require a strong ETag.
Solid weekly plans conditionally reserve one resource per week and reconcile
concurrent changes to different days. `savePlan` validates new recipe references
against the subjects known from list/create/update and works when destructured.

From the workspace root, with Node 24 on PATH:

```sh
pnpm exec turbo run lint build typecheck test --filter=@jeswr/solid-recipe
```
